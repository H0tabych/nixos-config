# Правила файлов в `modules/` (STRUCTURE.md, раздел 3)

- Каждый `.nix` без префикса `_` — flake-parts-модуль. Глубина ровно `modules/<домен>/<файл>.nix` (STR-2). Исключения — `hosts/` и `users/` при росте.
- Имя файла = имя фичи = ключ `flake.modules.<класс>.<имя>`. Имена файлов уникальны во всём `modules/`; `default.nix` запрещён (STR-4a).
- Реализация слота: `<слот>-<реализация>.nix`, суффиксы по таблице A.3 Архитектуры (STR-4b). Имена пресетов зарезервированы и фичам не даются.
- Первая строка — метаданные: `# Фича: <имя> · Слот: <слот|—> · Домен: <домен> · Классы: <N|H|N+H> · Для: <адресат>` (STR-5). Домен и имя совпадают с путём, классы — с фактически определёнными.
- Размер ≲ 150 строк (предупреждение), > 250 — ошибка. Растёт — делить по границе контракта, затем приватная часть `_<владелец>-…` рядом с владельцем (STR-6).
- Фича **не импортирует** другую фичу; зависимость выражается `assertions` с понятным сообщением (ARCH-3). Состав задают только `presets/` и `hosts/`.
- Параметры — только из `config.my.*`. Констант хоста, имён пользователей и секретов в фиче нет (ARCH-17, SEC-2).
- `mkForce`, `rec`, `with` на большой области — только с комментарием-причиной (ARCH-13).
- Пакет и overlay принадлежат фиче-владельцу; общая функция попадает в `core/lib.nix` только при втором потребителе (ARCH-11).
- Конфиг приложения из реестра — не здесь, а в репозитории dotfiles (DOT-3, SLOT-1).
- Новая фича: запись в каталоге Архитектуры (FEAT-7), строка в пресете-владельце (FEAT-8), затем проверка.
