# Дизайн-система рабочего стола «Glass Tide» — единый визуальный язык системы

> Версия 1.2 · 2026-10-17 · Статус: принят владельцем, вступает в силу с принятием ADR-36 (изменения 1.1: профиль `game` приведён в соответствие с DSN-MAT-4; DSN-LAY-4 уточнено для менеджера входа без смены раскладки; добавлены требования к отклику промпта и критерий DSN-A13; приняты решения по промпту, менеджеру входа и обоям; закрыты проверки по исходникам; добавлено Приложение I «Что нужно сделать»; изменения 1.2, ADR-38: DSN-CMP-12 — промпт без капсул-фона, обычным текстом с цветом-ролью — живая проверка на машине показала, что разделители-полукруги Nerd Font закрашивали соседние символы)
> **Подчинена** нормативному документу «Архитектура NixOS-систем» (далее — **Архитектура**): конкретизирует DESK-6 (тема — один владелец), DOT-9 (палитра — один источник), SLOT-4 (c) (цвета компонентов — из палитры) и DESK-9 (скрипты оболочки в dotfiles). Правила Архитектуры не дублируются — на них даются ссылки по ID. При расхождении приоритет у Архитектуры.
> **Части 0–12** — нормативные; в них нет имён конкретных программ, версий и шрифтов (ARCH-16, ARCH-18): только роли, слоты, токены и проверяемые пороги. **Приложение V** — значения токенов v1.0 и расчёт контрастов по обоим вариантам обоев. **Приложение S** — схема `palette.toml` и генератора. **Приложение P** — профиль реализации: конкретные программы, файлы, опции и версии канала 26.05. **Приложение R** — обоснование решений, замер отклика промпта и источники. **Приложение I** — что нужно сделать: решения, интеграция в документы, шаги ROADMAP, проверки на машине, замер промпта. Приложения информативны и меняются без ADR.

## 0. Подчинение и соглашения

**0.1 Что это.** Единые правила внешнего вида и поведения **всех** графических и терминальных интерфейсов хоста: композитора и его окон, менеджера входа, экрана блокировки, компонентов оболочки (панель, лаунчер, уведомления, OSD, агент полномочий, меню питания), терминала и всего, что в нём работает (шелл и его промпт, редактор, файловый менеджер, TUI-утилиты), GUI-тулкитов и прикладных программ capability `office`, `media`, `gaming`, `development`. Любая программа, которая появляется в системе, обязана соответствовать этому документу — или быть явно записана в исключения (раздел 8) с причиной.

**0.2 Что не дублируется.** Каталог слотов и контракты (Архитектура, раздел 6), dotfiles-слой и машинный слой (раздел 8 Архитектуры), правила рабочего стола DESK-1…DESK-10, структура репозиториев (STRUCTURE.md). Здесь — только то, *как выглядит и ведёт себя* интерфейс и *за счёт чего* это обеспечивается.

**0.3 Условие непротиворечивости.**
- Документ **не меняет** разделы 2, 3, 8–11 Архитектуры. DOT-9 и DESK-6 конкретизируются: палитра расширяется до полного набора дизайн-токенов (цвета, прозрачности, шрифты, размеры, движение), источник по-прежнему один — `theme/palette.toml` в dotfiles.
- Новые решения оформлены записью ADR-36 (раздел 12) и файлом в `docs/adr/`.
- Конкретные программы, их опции и версии живут только в Приложении P; смена реализации слота (ARCH-16) меняет строку Приложения P, а не нормативную часть.

**0.4 Соглашения.** MUST / MUST NOT / SHOULD / MAY — по RFC 2119. ID правил: `DSN-<область>-<n>`, области: `P` — принципы, `MAT` — материалы и стекло, `COL` — цвет, `TYP` — типографика, `SHP` — форма и сетка, `MOT` — движение, `LAY` — раскладка и видимость информации, `CMP` — требования к слотам, `EXC` — исключения, `PWR` — профили эффектов, `TOK` — конвейер токенов. Критерии приёмки — `DSN-A<n>`. `ПРОВЕРИТЬ` — как в п. 0.1.5 Архитектуры: не подтверждено на машине, дана проверка. Идентификаторы и пути — английские, текст — русский.

| Термин | Значение |
|---|---|
| Токен | Именованное значение дизайна (цвет-роль, альфа, размер шрифта, радиус, длительность). Определяется один раз в `palette.toml` |
| Роль | Смысловое имя цвета (`base`, `text`, `accent`, `error`…), а не его оттенок. Приложения ссылаются на роли |
| Оболочка (chrome) | Элементы управления системой: панель, лаунчер, уведомления, OSD, меню, рамки окон, экран блокировки |
| Контент | То, ради чего открыто окно: документ, страница, видео, игра, переписка, код |
| Стекло | Поверхность с тонировкой `α < 1` поверх размытого фона |
| Тонировка, `α` | Непрозрачность заливки стекла цветом роли `base`/`mantle`. `α = 1` — сплошная поверхность |
| Худшая точка | Цвет под текстом в самом неблагоприятном месте: тонировка поверхности, смешанная с самым светлым участком (99,5-й перцентиль яркости) размытых обоев каждого варианта; для сплошной поверхности — её фон |
| Вариант | Набор «обои + акцент». Нейтрали и семантика у вариантов общие |
| Профиль эффектов | Глобальный режим цены эффектов: `ac`, `battery`, `solid`, `game` (раздел 9) |

**0.5 Расположение.** Файл лежит рядом с Архитектурой (`docs/architecture/DESIGN_SYSTEM.md`), ссылка — из `docs/README.md`. Токены — в dotfiles (`theme/palette.toml`), генератор и шаблоны — `theme/gen/`, проверки — CI dotfiles (DOT-14). Решения — `docs/adr/`.

## 1. Цели, не-цели, принципы

### 1.1 Цели (по приоритету)

1. **Читаемость** любого текста в любом состоянии системы, на обоих вариантах обоев, с эффектами и без.
2. **Важное на виду**: состояние системы считывается взглядом, без кликов; редкое — по запросу.
3. **Единство**: все окна, панели и приложения выглядят как части одной системы — одни роли цвета, одни шрифты, одни радиусы и отступы.
4. **Предсказуемость**: одинаковые элементы выглядят и ведут себя одинаково; положение элементов стабильно.
5. **Экономность**: эффекты не съедают батарею и не вызывают подтормаживаний на встроенной GPU.
6. **Эстетика тёмного стекла** (glassmorphism) — в границах, которые задают цели 1–5.

### 1.2 Не-цели

- Палитра, извлекаемая из обоев автоматически: контраст непредсказуем, противоречит ADR-9. Связь с обоями задаётся вручную — вариантами (DSN-COL-9).
- Светлая тема в v1.0. Структура токенов её допускает (MAY в следующих версиях), но приёмка — только тёмной.
- Стилизация каждого приложения любой ценой. Если программа не темизируется штатно, она остаётся тёмной сплошной и записывается в исключения (раздел 8), а не ломается патчами.
- Анимированные и «живые» эффекты (переливы, частицы, анимированные рамки).

### 1.3 Принципы

| ID | Правило |
|---|---|
| DSN-P-1 | **Читаемость важнее эффекта.** При конфликте любого правила с порогами контраста (DSN-COL-4) побеждают пороги: поднимается тонировка, отключается стекло — но не снижается контраст. |
| DSN-P-2 | **Стекло — для оболочки и терминала, не для контента.** Окна, где читают и смотрят (браузер, документы, почта, мессенджер, видео, игры), — сплошные (DSN-MAT-2, раздел 8). |
| DSN-P-3 | **Прозрачна заливка, а не окно.** Полупрозрачность задаётся фоном поверхности; текст, иконки и рамки всегда непрозрачны (DSN-MAT-3). |
| DSN-P-4 | **Глубина — светлотой и плотностью.** Чем выше слой, тем светлее и плотнее его поверхность; тени — вспомогательный канал, не основной. |
| DSN-P-5 | **Важное на виду, остальное по запросу.** Каждый индикатор отнесён к зоне внимания (раздел 6); всё, что не в списке «всегда видно», скрыто до наведения или события. |
| DSN-P-6 | **Цвет — сигнал, и никогда не единственный.** Любое состояние передаётся формой или текстом **и** цветом (DSN-COL-8). |
| DSN-P-7 | **Одно значение — один токен** (ARCH-5, L-8). В конфигах приложений нет собственных цветов, шрифтов, радиусов и длительностей — только ссылки на сгенерированные токены (DSN-TOK-1, DSN-TOK-8). |
| DSN-P-8 | **Спокойствие.** Движение короткое и функциональное: показывает, откуда пришло и куда ушло. Ничего не мигает и не анимируется без действия пользователя или события. |
| DSN-P-9 | **Деградация без потерь.** При выключенных эффектах (профили `battery`, `solid`, `game`) интерфейс остаётся полным: та же раскладка, те же индикаторы, та же иерархия. |
| DSN-P-10 | **Проверяемость.** Каждое числовое правило проверяется автоматически (генератор, CI) или по чек-листу раздела 11. Правило, которое нельзя проверить, переписывается. |

## 2. Материалы и стекло

### 2.1 Уровни материала

Каждая поверхность системы относится ровно к одному уровню. Уровень определяет тонировку, размытие, рамку и тень. Значения — для профиля `ac`; другие профили — раздел 9.

| Уровень | Что | Заливка | `α` | Размытие | Рамка | Тень |
|---|---|---|---|---|---|---|
| **L0 Фон** | обои рабочего стола | изображение варианта | — | — | — | — |
| **L1 Стекло панели** | капсулы панели | `base` | 0.80 | да | ободок 1 px | нет |
| **L2 Стекло окна** | окна терминала (и всё, что внутри: шелл, редактор, файловый менеджер, TUI) | `base` | 0.88 | да | рамка окна (DSN-SHP-3) | да |
| **L3 Временные** | лаунчер, уведомления, OSD, меню питания, подсказки и выпадающие меню оболочки | `mantle` | 0.90 | да | ободок 1 px | да |
| **L4 Сплошные** | все GUI-окна с контентом, диалоги приложений | `base` / `surface0` | 1.0 | нет | рамка окна | да |
| **L5 Критические** | критические уведомления, запрос пароля и полномочий, подтверждение разрушительных действий | `mantle` | 1.0 | нет | 2 px `error` или `accent` | да |
| **L6 Экран входа и блокировки** | менеджер входа, экран блокировки | размытые обои + затемнение | — | своё | — | — |

### 2.2 Правила

| ID | Правило |
|---|---|
| DSN-MAT-1 | Каждая поверхность MUST относиться к одному уровню 2.1. Новая поверхность (новое приложение, новый модуль панели) получает уровень в том же изменении — строкой в Приложении P. |
| DSN-MAT-2 | **Минимальная тонировка определяется содержимым поверхности:** только основной текст и иконки — `α ≥ 0.78`; есть вторичный или приглушённый текст (метаданные, плейсхолдеры, комментарии кода) — `α ≥ 0.85`; длительное чтение или просмотр — `α = 1` (L4). Пороги выведены расчётом по обоим вариантам обоев (Приложение V.3) и пересчитываются при смене обоев или нейтралей. |
| DSN-MAT-3 | Полупрозрачность **всего окна** средствами композитора (непрозрачность активного/неактивного окна) MUST NOT применяться к окнам с текстом: значение — 1.0. Прозрачность задаётся только альфой фона внутри приложения или поверхности. |
| DSN-MAT-4 | Стекло с `α < 0.94` MUST иметь размытие фона. Без размытия (профили `battery` и `game`) тонировка поднимается до `α ≥ 0.94`. |
| DSN-MAT-5 | Размытие MUST делать детали обоев неразличимыми (на скриншоте нельзя узнать предметы под стеклом) и слегка затемнять фон (яркость размытого слоя ≤ 0.9 от исходной). Шум — не более 2 %. Анимированные и искажающие варианты размытия запрещены. |
| DSN-MAT-6 | Стеклянные поверхности L1 и L3 MUST иметь ободок 1 px цвета `text` с альфой 0.06–0.10: он отделяет стекло от стекла и от светлых участков обоев. |
| DSN-MAT-7 | Размытие поверхностей с прозрачными полями (тени, скругления, отступы оболочки) MUST игнорировать пиксели с альфой ниже 0.2, иначе размывается «пустота» вокруг капсул. |
| DSN-MAT-8 | Затемнение неактивных окон MAY применяться с силой ≤ 0.10; при этом основной текст неактивного окна MUST оставаться ≥ 7:1. |
| DSN-MAT-9 | Тени — только мягкие, без смещения, цвета `crust`; у неактивных окон слабее, чем у активного. У панели теней нет. |

## 3. Цвет

### 3.1 Роли

Значения ролей — Приложение V.1; источник — `palette.toml` (DOT-9).

| Группа | Роли | Назначение |
|---|---|---|
| Поверхности | `crust` → `mantle` → `base` → `surface0` → `surface1` → `surface2` | от самого глубокого к самому высокому; `base` — основной фон и тонировка стекла |
| Линии | `overlay0` | декоративные разделители, неактивные рамки; не для текста |
| Текст | `text` → `subtext1` → `subtext0` → `overlay1` | основной → важный вторичный → вторичный → приглушённый (комментарии, плейсхолдеры, метаданные) |
| Акценты | `accent` (сменный по варианту), `accent_warm` (общий), `on_accent` | фокус и выбор; тёплый декор; текст поверх акцента и семантики |
| Семантика | `success`, `warning`, `error`, `info`, `special` | статусы; общие для всех вариантов |
| Терминал | `ansi.regular[0..7]`, `ansi.bright[0..7]`, `selection`, `cursor` | 16 цветов терминала и связанные роли |

### 3.2 Правила

| ID | Правило |
|---|---|
| DSN-COL-1 | Цвета определяются **только** в `palette.toml` (DOT-9). Конфиги приложений ссылаются на роли из сгенерированных файлов; литерал цвета в конфиге вне сгенерированного файла — дефект (проверка — DSN-TOK-8). |
| DSN-COL-2 | Основа тёмная и холодная: `base` — не чистый чёрный, тон 195–215° (между тёмными доминантами обоих вариантов обоев, Приложение V.2), относительная яркость ≤ 0.015. `text` — не чистый белый, контраст к `base` в диапазоне 12:1–16:1 (меньше «ореола» у людей с астигматизмом при запасе выше AAA). |
| DSN-COL-3 | Лестница поверхностей монотонна по светлоте: `crust < mantle < base < surface0 < surface1 < surface2`. Иерархия выражается шагом светлоты, а не оттенком. |
| DSN-COL-4 | **Пороги контраста в худшей точке** (0.4) — для каждого варианта обоев и каждого профиля эффектов. Проверяются генератором (DSN-TOK-3): |
| | • `text` — ≥ 7:1 (WCAG 2.x) и Lc ≥ 75 (APCA) |
| | • `subtext1` — ≥ 7:1 и Lc ≥ 65 |
| | • `subtext0` — ≥ 4.5:1 и Lc ≥ 55 |
| | • `overlay1` и `ansi.bright[0]` (приглушённый текст) — ≥ 4.5:1 и Lc ≥ 40 |
| | • семантика и `ansi.regular[1..7]`, `ansi.bright[1..7]` как цвет текста — ≥ 4.5:1 и Lc ≥ 45 |
| | • `on_accent` на `accent` и на каждой семантической роли — ≥ 7:1 |
| | • `text` на `selection` — ≥ 7:1 |
| | • неглавные визуальные индикаторы (рамка фокуса, индикатор рабочего стола, полосы прогресса, переключатели) — ≥ 3:1 к соседнему цвету |
| | `overlay0` — только декоративные элементы, порогов нет, но информацию не несёт. |
| DSN-COL-5 | `accent` — один на вариант. Применяется для фокуса, текущего выбора, активного рабочего стола, курсора, ссылок, включённых режимов. MUST NOT обозначать статус (успех/ошибка/предупреждение). |
| DSN-COL-6 | `accent_warm` — только декоративный (градиент рамки фокуса, часы, ветка VCS в промпте). Смысла не несёт, не используется для статусов и предупреждений. |
| DSN-COL-7 | Семантика фиксирована: `error` — ошибка, критично, разрушительное действие; `warning` — внимание, низкий заряд; `success` — норма, подключено, туннель поднят; `info` — нейтральная информация; `special` — режимы и метрики (время выполнения команды, VCS-операции). `accent` и `success` различимы по тону (разница ≥ 30°). |
| DSN-COL-8 | Цвет MUST NOT быть единственным каналом: каждое состояние имеет форму (иконка, капсула-фон, рамка) или текст. Проверка — скриншот в оттенках серого (DSN-A6). |
| DSN-COL-9 | **Варианты обоев.** Нейтрали, семантика и ANSI общие для всех вариантов; вариант задаёт только обои, `accent` и связанные с ним производные (цвет папок иконок). Активный вариант выбирается одним ключом; каждый вариант обязан проходить DSN-COL-4. |
| DSN-COL-10 | **16 цветов терминала** выводятся из ролей: `regular[0]` = `surface1` (используется как фон элементов), `bright[0]` = `overlay1`, `regular[7]` = `subtext1`, `bright[7]` = `text`; `1..6` = `error`, `success`, `warning`, `info`, `special`, бирюзовый (`teal`). Значения `bright[1..6]` — светлее `regular` на одном тоне. Фон терминала — `base`, текст — `text`. |
| DSN-COL-11 | Выделение текста: фон `selection` (= `surface2`), цвет текста сохраняется. Курсор текста — `accent`. |
| DSN-COL-12 | Производные форматы (base16/base24 и т. п.) MAY генерироваться для сторонних потребителей; источником не являются и вручную не правятся. |

## 4. Типографика

## 6. Раскладка рабочего стола и видимость информации

### 6.1 Панель и зоны внимания

**DSN-LAY-1.** Панель — вертикальная, у левого края, ширина 44 px, отступ от края 8 px, сверху и снизу 12 px; модули сгруппированы в капсулы L1. Причина: на экране 16:9 дефицитна высота, а не ширина; вертикальная панель отнимает 2,3 % ширины и не трогает строки кода и текста.

**DSN-LAY-2.** Модули панели распределены по четырём зонам сверху вниз:

| Зона | Содержимое | Видимость |
|---|---|---|
| 1. Навигация | кнопка лаунчера; рабочие столы (активный — `accent`, занятый — `subtext0`, пустой — `overlay1`, срочный — `error`) | всегда |
| 2. Внимание | индикаторы приватности (запись экрана, микрофон, камера), «не беспокоить», запрет сна, медиа | только при активном событии или режиме |
| 3. Состояние | раскладка (`EN`/`RU`), туннель/VPN, сеть, звук и микрофон, батарея; раскрывающаяся капсула «ещё»: яркость, Bluetooth, трей | первые — всегда, «ещё» — по наведению |
| 4. Время и питание | часы (часы над минутами), дата и календарь во всплывающей подсказке; кнопка меню питания | всегда |

## 9. Профили эффектов и энергосбережение

| Параметр | `ac` (от сети) | `battery` | `solid` | `game` |
|---|---|---|---|---|
| Размытие | да | нет | нет | нет |
| Тонировка L1 / L2 / L3 | 0.80 / 0.88 / 0.90 | 0.94 / 1.0 / 0.94 | 1.0 / 1.0 / 1.0 | 0.94 / 1.0 / 0.94 |
| Тени | да | нет | да | нет |
| Анимации | 1.0× | 0.6× | выкл. для окон | выкл. |
| Затемнение неактивных | да | да | да | нет |

Частота обновления встроенного экрана — максимальная на всех профилях, без исключений: понижение на `battery` было MAY, исключено по итогам M8 (DSN-S7/R6.10) — Hyprland 0.55 не даёт сменить режим монитора на лету без `hyprctl eval`, которой в этой сборке нет (`hyprctl keyword` отвечает «can't work with non-legacy parsers»).

Профили без размытия (`battery`, `game`) используют тонировку оболочки 0.94 (DSN-MAT-4): при 0.80 без размытия приглушённый текст на самом светлом участке обоев A опускается ниже порога (Lc 52 при требуемых 55), а `overlay1` — ниже 4.5:1.

| ID | Правило |
|---|---|
| DSN-PWR-1 | Профиль — одна переменная состояния пользователя; все компоненты читают её и сами не решают, какие эффекты включать. |
| DSN-PWR-2 | `ac` ↔ `battery` переключаются автоматически по источнику питания; `solid` и `game` — вручную (сочетание клавиш, пункт меню) и автоматически снимаются при выходе из сессии. |
| DSN-PWR-3 | Переключение применяется к работающей сессии за ≤ 2 с, без перезапуска сессии и без потери окон. |
| DSN-PWR-4 | Все профили проходят DSN-COL-4 и сохраняют раскладку и индикаторы (DSN-P-9). |
| DSN-PWR-5 | Профиль `solid` — системный аналог «уменьшить прозрачность»: доступен в любой момент и MAY быть выбран по умолчанию. |
| DSN-PWR-6 | Цена эффектов проверяется измерением (потребление на батарее, частота кадров), а не на глаз (DSN-A10). Если `ac` вызывает подёргивания — сначала уменьшается число проходов размытия, затем его радиус. |
| DSN-PWR-7 | Состояние профиля хранится в каталоге состояния пользователя (`$XDG_STATE_HOME`), не в dotfiles и не в машинном слое: это не конфиг и не факт хоста. Если состояние отсутствует — действует `ac`. |

## 11. Приёмка

### 11.1 Критерии

| № | Критерий | Как проверяется |
|---|---|---|
| DSN-A1 | Генератор проходит DSN-COL-4 для всех вариантов и профилей | CI dotfiles, лог генератора |
| DSN-A2 | В dotfiles и Nix-коде нет литералов цвета и размеров вне сгенерированных файлов и `palette.toml` | скрипт DSN-TOK-8 |
| DSN-A3 | Контраст на живой системе: скриншоты каждой стеклянной поверхности над самым светлым участком **каждых** обоев; пипеткой снятый фон под текстом даёт значения DSN-COL-4 | ручная проверка на живой системе; скриншоты — только рабочий инструмент проверки (пипетка, тест прищуривания), не сохраняются и не прикладываются к коммиту |
| DSN-A4 | Детали обоев под стеклом неразличимы (DSN-MAT-5) | визуально по тем же скриншотам |
| DSN-A5 | **Тест прищуривания:** при расфокусированном взгляде (или размытии скриншота) видно активное окно, раскладку, батарею, сеть, время и любой критический индикатор | ручная проверка |
| DSN-A6 | Скриншот в оттенках серого: все состояния различимы без цвета (DSN-COL-8) | ручная проверка |
| DSN-A7 | Раскладка видна в панели и на экране блокировки; менеджер входа без смены раскладки работает в раскладке по умолчанию (DSN-LAY-4); кириллица во всех шрифтах без подстановок | визуально; проверка подбора шрифтов для кириллицы |
| DSN-A8 | Окна исключений (раздел 8) — сплошные, без размытия; видео и игры определяются автоматически | список окон композитора и их правила |
| DSN-A9 | Профили: `battery` включается от отключения сети за ≤ 2 с; `solid` и `game` переключаются сочетанием клавиш; после переключения нет упавших пользовательских юнитов | `systemctl --user --failed` пуст |
| DSN-A10 | На профиле `ac` нет подёргиваний при максимальной частоте экрана; потребление на `battery` не выше, чем без дизайна (сравнение замеров) | замер, журнал в runbook |
| DSN-A11 | Смена варианта одной командой перекрашивает всё: оболочку, терминал, промпт, редактор, GTK/Qt, менеджер входа (после пересборки), обои | ручная проверка по Приложению P |
| DSN-A12 | Галерея: по скриншоту каждого приложения из Приложения P — единые шрифты, радиусы, рамки, роли цвета | ручная проверка |
| DSN-A13 | Отклик промпта (DSN-CMP-12): медиана ≤ 30 мс в рабочих репозиториях, максимум ≤ 100 мс в самом большом из них | скрипт замера на машине (Приложение I.7), результат — в журнал |

### 11.2 Процедура

1. Сгенерировать токены, прогнать проверки (DSN-A1, DSN-A2); замерить отклик промпта (DSN-A13, Приложение I.7).
2. Для каждого варианта обоев: включить вариант, профиль `ac`; снять скриншоты панели, лаунчера, уведомления (обычного и критического), OSD, терминала с редактором и файловым менеджером, GTK- и Qt-окна, экрана блокировки. Повторить для `battery` и `solid`.
3. Проверить DSN-A3…DSN-A8 по скриншотам.
4. Неделю пользоваться системой (по образцу наблюдения R4.7); всё, что мешает читать или отвлекает, — в журнал регрессий; правки только через токены.

## S.2 Генератор

- Язык — Python ≥ 3.11 **только со стандартной библиотекой** (`tomllib`, `string.Template`, `zipfile`, `math`): работает на любой системе без зависимостей (переносимость dotfiles, DOT-8). Текущий `generate.sh` (bash + sed, плоская секция `[colors]`) заменяется; шаблоны `__key__` переводятся на `${key}`.
- Вход: `palette.toml`, активный вариант; выход — файлы таблицы ниже, по одному на потребителя и при необходимости на профиль (DSN-TOK-7).

- Команды: `theme/gen/gen.py` — сгенерировать; `--check` — только проверки (CI); `--variant forest` — сменить вариант и сгенерировать; `--export base24` — производные форматы.

## S.3 Проверки генератора (`--check`)

1. Схема: все роли и токены на месте, HEX валиден, альфы в [0, 1], шкала шрифтов ровно из пяти размеров (DSN-TYP-2).
2. DSN-COL-3: монотонность светлоты поверхностей.
3. DSN-COL-4 для каждого варианта × профиля: цвет под текстом = `glass.<профиль>.<уровень>`·`base` + (1 − α)·`probe` (`probe.screen` для L2/L3, `probe.bar` для L1, `*_sharp` — если в профиле нет размытия); пороги WCAG и APCA — по таблице DSN-COL-4.
4. DSN-COL-7: разница тона `accent` и `success` ≥ 30° для каждого варианта.
5. DSN-TOK-8: поиск литералов (`#[0-9a-fA-F]{6}`, `rgb(`, `rgba(`, имена семейств из `[font]`) в dotfiles вне сгенерированных файлов и `palette.toml`.
6. Обои: файл `theme/wallpapers/<file>` существует, его `sha256` совпадает с записанным в варианте; иначе контрольные точки `probe` могут быть посчитаны для другого изображения — пересчитать `probe.py` и обновить запись (DSN-TOK-10).

Контрольные точки `probe` пересчитывает отдельный вспомогательный скрипт (`theme/gen/probe.py`, требует библиотеку изображений; запускается вручную при смене обоев, результат коммитится в `palette.toml`), поэтому основному генератору изображения не нужны.

# Приложение R. Обоснование и источники (информативно)

## R.1 Ключевые решения

| Решение | Почему | Отвергнутая альтернатива |
|---|---|---|
| Стекло только для оболочки и терминала | Fluent: акрил — для временных поверхностей, для долгоживущих окон — непрозрачный Mica; NN/g: главный риск стекла — читаемость текста, применять умеренно | стекло на всех окнах (референсы r/unixporn) — длительное чтение на «живом» фоне |
| Прозрачна заливка, а не окно | непрозрачность окна композитором делает полупрозрачным и текст | `active_opacity`/`inactive_opacity` < 1 (предлагалось во внешнем исследовании) |
| Минимальная тонировка 0.78/0.85 по расчёту | при 0.2–0.5 над светлым горизонтом текст падает до ≈ 1.9–3.9:1 | «прозрачная панель 15–20 %» из внешнего исследования |
| Холодная тёмная основа, не чистый чёрный и не чистый белый | рекомендации тёмных тем Material; меньше ореола (halation) | `#000000`/`#FFFFFF`; нейтральный серый `#121212` — спорит с бирюзовыми обоями |
| Десатурированные пастельные акценты | насыщенные цвета «вибрируют» на тёмном фоне | `#00BFFF`, `#F44336` и подобные |
| WCAG + APCA | WCAG 2 завышает контраст тёмных пар; APCA точнее для тёмной темы, но ещё не стандарт — проверяем оба | только WCAG |
| Вертикальная панель | на 16:9 дефицитна высота | горизонтальная панель 30–40 px |
| Масштаб 1.0 + крупная шкала шрифтов | дробный масштаб размывает клиентов совместимости X11 (Steam и др.) | масштаб 1.25 |
| Профили эффектов | композитор рендерит на встроенной GPU; батарея 48 Вт·ч | всегда включённые эффекты |
| Собственная палитра с вариантами вместо извлечения из обоев | ADR-9; контраст должен быть гарантирован | pywal/wallust/matugen |
| Генератор на стандартной библиотеке Python | переносимость dotfiles без зависимостей; проверка контраста | sed-шаблоны (нет вложенных структур и проверок), Jinja2 (зависимость) |
| Промпт — starship с внешним `git` и таймаутом статуса VCS 50 мс | Замер R.4: встроенная библиотека git не соблюдает таймаут (291 мс в репозитории из 55 тыс. файлов), внешний `git` — соблюдает (73 мс); остальной промпт укладывается в 5–18 мс | конфиг по умолчанию (583 мс в том же репозитории); отказ от статуса VCS (теряется заметный индикатор) |
| Менеджер входа — SDDM с темой sddm-astronaut; раскладка до входа не показывается | Wayland-греттер SDDM не реализует смену раскладки, тема её не показывает (I.6); пароль вводится в раскладке по умолчанию | собственная QML-тема; X11-греттер ради индикатора |

## R.4 Замер отклика промпта (2026-10-14)

Один вызов = один запуск процесса, как в оболочке; оболочка вызывает промпт дважды на каждое приглашение (левая и правая части), в таблице — сумма, медиана, мс; разброс между повторами ±2 мс. Репозитории: 145 файлов (этот), 1 314 файлов (Hyprland), 54 971 файл (nixpkgs); во всех — изменённый и неотслеживаемый файл.

|---|---|---|---|---|
| по умолчанию (все модули) | 6,9 | 20,8 | 27,0 | 583 |
| шаблон P.3.5 со встроенной библиотекой git, `command_timeout = 200` | 5,9 | 17,8 | 23,5 | 291 |

Нижняя граница — запуск пустой программы: 1,6–2,2 мс. Инициализация `eval "$(starship init zsh)"` добавляет к запуску оболочки около 6 мс.

Выводы:

1. Вне огромных репозиториев промпт укладывается в 5–18 мс. Слагаемые: запуск процесса (≈ 2 мс на вызов), поиск репозитория модулями каталога и ветки (≈ 4–5 мс) и статус VCS (≈ 5 мс в маленьком репозитории).
2. `command_timeout` и `scan_timeout` **не ограничивают** встроенную библиотеку git: в репозитории из 55 тыс. файлов промпт с `command_timeout = 200` ждал 291 мс, с конфигом по умолчанию — 583 мс. Внешний `git` таймаутом ограничивается: промпт отбрасывает сегмент статуса и укладывается примерно в 73 мс.
3. Конфиг по умолчанию медленнее на 6–9 мс в обычных репозиториях и в 8 раз в огромном. Модули языков в измерении не участвовали (в стенде нет тулчейнов) — они запускают внешние программы за версией и поэтому исключены из формата (DSN-CMP-12).
4. Причина неудовлетворительного отклика, о которой сообщил владелец при прошлой попытке, не установлена; наиболее вероятные кандидаты — статус VCS в большом репозитории и конфиг по умолчанию. Проверяется замером на ноутбуке (DSN-S1).

## I.5 Порядок работы внутри шага

1. Назвать ID шага и критерий готовности; показать список файлов и изменений (правило 6 `CLAUDE.md`); получить согласие.
2. Правка dotfiles видна на машине сразу (DOT-4); правка `nixos-config` — только через `just check`, затем `build` → `nvd diff` → `test` → `boot` (OPS-3). Прямой `switch` запрещён до G9 (W3).
3. После шага — живая проверка и замеры из критерия готовности (скриншоты — рабочий инструмент проверки, не сохраняются); запись в журнал; коммит с ID шага ROADMAP (`R6.8: оболочка в стиле Glass Tide`).
4. Всё, что не удалось проверить, остаётся с пометкой `ПРОВЕРИТЬ` и номером из I.6.

## I.7 Замер отклика промпта

Критерий — DSN-A13: медиана ≤ 30 мс в рабочих репозиториях (≤ 5 000 файлов), максимум ≤ 100 мс в самом большом. Оболочка вызывает промпт дважды на каждое приглашение (левая и правая часть), поэтому скрипт мерит оба вызова и складывает. Запуск — после установки `starship`, с принятым конфигом; каталоги — реальные рабочие репозитории и самый большой из них:

```
python3 bench-prompt.py --config ~/.config/starship/starship.toml ~/.dotfiles ~/Projects/<репозиторий> <самый-большой-репозиторий>
```

Скрипт принимает только существующий файл конфига: при неверном пути starship молча берёт конфиг по умолчанию, и замер получается о другом конфиге.

```python
#!/usr/bin/env python3
"""Замер отклика промпта starship: медиана, p95 и максимум в мс (левая и правая части)."""
import argparse, os, statistics, subprocess, sys, time

def run(cmd, env, cwd):
    t = time.perf_counter()
    subprocess.run(cmd, env=env, cwd=cwd, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    return (time.perf_counter() - t) * 1000

def stats(xs):
    xs = sorted(xs)
    return statistics.median(xs), xs[round(0.95 * (len(xs) - 1))], xs[-1]

ap = argparse.ArgumentParser()
ap.add_argument("--runs", type=int, default=100)
ap.add_argument("--config", required=True)
ap.add_argument("dirs", nargs="+")
a = ap.parse_args()
cfg = os.path.abspath(a.config)
if not os.path.isfile(cfg):
    sys.exit(f"нет файла конфига: {cfg}")
env = dict(os.environ, STARSHIP_SHELL="zsh", STARSHIP_SESSION_KEY="bench", STARSHIP_CONFIG=cfg)
args = ["--status=0", "--jobs=0", "--cmd-duration=0", "--terminal-width=120"]
left, right = ["starship", "prompt", *args], ["starship", "prompt", "--right", *args]
base = stats([run(["true"], env, "/") for _ in range(a.runs)])  # NixOS: /bin/true нет, ищем в PATH
print(f"fork+exec пустой программы: медиана {base[0]:.1f} мс")
print(f"{'каталог':<28}{'медиана':>9}{'p95':>8}{'макс':>8}   (левая + правая, мс)")
for d in map(os.path.abspath, a.dirs):
    xs = [run(left, env, d) + run(right, env, d) for _ in range(a.runs + 10)][10:]
    m, p, x = stats(xs)
    print(f"{os.path.basename(d) or d:<28}{m:9.1f}{p:8.1f}{x:8.1f}")
```

Если не проходит:

1. `starship timings` в проблемном каталоге: модуль, который дольше остальных. В измерениях R.4 им был `git_status` в большом репозитории.
2. Для такого репозитория подключить `starship-lite.toml` (тот же конфиг без `$git_status`, создаётся генератором — S.2) через `.envrc` репозитория: `export STARSHIP_CONFIG=~/.config/starship/starship-lite.toml`. На репозитории из 55 тыс. файлов это 11 мс вместо 73 мс (R.4).
3. Если и это не устраивает — заменить реализацию слота `prompt` (ARCH-16, 18.5 Архитектуры): требования DSN-CMP-12 остаются теми же.
