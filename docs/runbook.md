# Runbook

Единственная точка входа для операционных процедур (STR-12, OPS-8). Длинные
процедуры по темам — в `runbook/<тема>.md`, со ссылкой отсюда.

Приватные сведения (операторы, уязвимости действующей системы, данные
учётных записей) здесь не хранятся — только вне репозитория (STR-12,
VPN_SUBSYSTEM.md P.6/P.7).

## Темы

- [`runbook/tunnel.md`](runbook/tunnel.md) — туннель: реестр отступлений (VPN-CLI-3), upstream для LLM
  (VPN-LLM-1…6), процедура изменения конфига выхода (VPN-SRV-7)
- [`runbook/storage.md`](runbook/storage.md) — хранилище: снимки и восстановление
  (STO-8, A11), откат поколения (OPS-5), scrub (STO-9), гибернация (STO-5)
- [`runbook/design-system.md`](runbook/design-system.md) — дизайн-система Glass
  Tide: журнал замеров (DSN-A9, DSN-A10, DSN-A13), ручное переключение профилей
  эффектов

## Бюджет ёмкости (STO-11)

Накопитель ≤ 512 ГБ, поэтому бюджет **утверждается до установки** и
пересматривается при изменении состава (игры, модели, рост `/nix`).

### `sgms-laptop` — Intel SSDPEKNU512GZ, 512 ГБ (≈ 476 ГиБ)

| Потребитель | Том / подтом | Бюджет | Основание |
|---|---|---|---|
| Загрузчик | ESP `/boot` | 1 ГиБ | `storage/layout`; 10 поколений с ядром и initrd |
| Swap | `@swap` → `/swap` | 28 ГиБ | ≥ RAM 24 ГиБ с запасом (STO-4, `my.host.swap.sizeMiB`) |
| Хранилище пакетов | `@nix` → `/nix` | 150 ГиБ | замыкания CUDA/ML, два канала, **поколения не удаляются до PNR-3** (W5) |
| Корень | `@rootfs` → `/` | 10 ГиБ | состояние системы без `/nix`, `/home`, логов |
| Данные пользователя | `@home` → `/home` | 80 ГиБ | конфиги, проекты, `~/.cache` |
| Логи | `@log` → `/var/log` | 5 ГиБ | journald с лимитом |
| Снимки | `@snapshots` → `/.snapshots` | 40 ГиБ | хранение `14d 8w` (`storage/backup`) |
| Вне снимков и бэкапа | `@data` → `/var/lib/nosnapshot` | 90 ГиБ | модели, игровая библиотека, образы контейнеров (STO-1) |
| **Резерв** | — | **72 ГиБ (≥ 15 %)** | порог тревоги STO-11 |

Btrfs — один пул: это **бюджеты, а не квоты** (qgroups не включены). Цифры —
ориентир для тревоги и планирования, а не ограничение, которое ФС применит сама.

Самая тесная строка — `@data`: 90 ГиБ на модели **и** игровую библиотеку
одновременно. При добавлении крупной игры или второй модели бюджет
пересматривается, а не молча превышается.

### Порог тревоги

```sh
# Свободное место в пуле (btrfs: df лжёт, смотреть именно так)
btrfs filesystem usage /
```

Тревога при свободном < 15 %. Порядок действий — по возрастанию риска:

1. Снимки: сократить срок хранения (`snapshot_preserve` в `storage/backup`).
2. Кэши: `~/.cache`, кэш сборок, образы контейнеров.
3. `@data`: модели и игры, которые можно скачать заново.
4. Сборка мусора: `nix-collect-garbage` **без** `--delete-older-than`.

**Поколения до PNR-3 не удалять** (W5): это единственный путь откатиться
(OPS-5, A11). `nix.gc` поэтому запущен без `options`; из-за этого GC
освобождает меньше, чем мог бы, — плата принята осознанно.
