# Runbook — восстановление

Порядок действий, когда система сломана или потеряна. Правила — OPS-3, OPS-5, STO-8, SEC-12, SEC-13;
критерии — A11, A2 (`grep -n "A11" docs/architecture/ARCHITECTURE.md`).

> Все команды выполняет человек. Разметку (`disko`), `mkfs`, `cryptsetup` и удаление поколений
> ассистент не запускает (ROADMAP W10).

## 1. Выбор уровня (от дешёвого к дорогому)

| Что случилось | Что делать | Где описано |
|---|---|---|
| Новая сборка не грузится или ведёт себя плохо | Откат поколения: меню systemd-boot или `nixos-rebuild boot --rollback` | [`storage.md`](storage.md) §4 |
| Не тот файл, удалена правка, сломан конфиг в `~` | Файл из снимка btrbk | [`storage.md`](storage.md) §3.1 |
| Испорчен подтом `home` или `rootfs` | Подтом из снимка | [`storage.md`](storage.md) §3.2 |
| Диск потерян или разметка разрушена | Переустановка (раздел 2) + данные из внешней копии | [`storage.md`](storage.md) §2, §3.3 |
| Не поднимается сеть после смены туннеля | Консоль + откат поколения; kill switch | [`tunnel.md`](tunnel.md), процедура 2 |
| Не расшифровываются секреты | Ключи: проверить ключ хоста и получателей | [`keys.md`](keys.md) |
| Модель, шлюз или песочница агентов не работают | Процедуры ML и агентов | [`ai.md`](ai.md) |

Поколения до PNR-3 не удаляются (W5), поэтому откат всегда доступен; место освобождают по порогу
тревоги из [`../runbook.md`](../runbook.md), а не удалением поколений.

## 2. Переустановка на чистую машину

Порядок по ARCHITECTURE.md §18.9: образ установщика → разметка → ключ хоста → установка из flake →
первый вход → `just dotfiles-clone` → приёмка (раздел 20).

> **Не автоматизировано.** `just bootstrap <хост>` — заготовка: выводит ссылку на §18.9 и завершается
> ошибкой (`justfile`). Автоматическая установка не реализована; шаги ниже выполняются вручную, а
> команды разметки и установки `ПРОВЕРИТЬ` по актуальной документации перед запуском — в репозитории
> они не записаны.

1. **Образ установщика** NixOS стабильного канала 26.05 (канал проекта — AGENTS.md). Сеть — до
   входа в туннель, напрямую.
2. **Ключ хоста — до первой активации (SEC-12).** Без SSH host-ключа ed25519, чей age-получатель
   записан в `.sops.yaml`, активация не расшифрует секреты. Источник: внешняя копия (подтом `rootfs`
   содержит `/etc/ssh`, SEC-13) либо офлайн-копия ключей. Если ключ потерян — завести новый и
   перешифровать секреты по [`keys.md`](keys.md) раздел 2, 3 (понадобится ключ пользователя).
3. **Разметка** — декларативная (`storage/layout`, `docs/hosts/sgms-laptop.md`, бюджет — в
   [`../runbook.md`](../runbook.md)). Разметка и `swap` меняют диск: запускает только человек, откат —
   перезапуск установки.
4. **Установка из flake** (`nixos-install --flake .#sgms-laptop`, `ПРОВЕРИТЬ` — флаги и корень
   монтирования). Для гибернации после создания swap-файла вычислить `resume.offset`
   (`just hibernate-offset`, STO-5).
5. **Первый вход.** Приложения реестра стартуют без конфигов, пока не клонированы dotfiles.
6. **Dotfiles:** `just dotfiles-clone` (путь и адрес берутся из `flake.lock` и `dotfilesClonePaths`).
7. **Данные пользователя** — из внешней копии (`storage.md` §2, §3.2); модели и игры — вне снимков
   (STO-1), скачиваются заново.
8. **Приёмка:** `just check`, затем критерии A1–A18 по разделу 20 ARCHITECTURE.md.

## 3. После восстановления

- Проверить `systemctl --user --failed` (A4) и `systemctl --failed`.
- Применить обновления по OPS-3 (`just build` → `nvd diff` → `just test` → `just boot`), не минуя шагов.
- Записать инцидент в журнал наблюдения (R9.10) и результат проверки восстановления — в таблицу
  [`storage.md`](storage.md) §3.3.
