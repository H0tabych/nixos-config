# ADR-34: ARCH-1 — владелец механизма ≠ источник данных; вклад в опцию-интерфейс владением не является

- Статус: принято
- Источник: ARCHITECTURE.md §2 (ARCH-1), §21; ROADMAP.md D6; VPN_SUBSYSTEM.md 4.4
- Решение: владелец ресурса определяет **опцию-интерфейс**, в которую вкладываются
  другие фичи. Вклад в чужую опцию-интерфейс не делает вкладчика вторым владельцем
  и ARCH-1 не нарушает. Данные, известные только вкладчику, поступают владельцу
  через эту опцию, а не записью в общий файл мимо владельца.
- Причина: ARCH-1 в прежней формулировке различал только «один файл = один
  владелец» и не отделял владение механизмом от происхождения данных. Из-за
  этого фиче `vpn-client` было некуда отдать DNS-зоны, которые она узнаёт из
  `PUSH_REPLY` сервера: владелец системного резолвера — `dns-resolver`, но
  значение знает только владелец линка. Единственным выходом оставался
  `updateResolvConf` в самой фиче, то есть плоский `resolv.conf` — корпоративный
  DNS видел личные запросы, внутренние имена утекали к публичным резолверам, а
  VPN-DNS-6 (запрет отката на DNS провайдера) становился невыразим: плоский
  список и есть откат (D6).
- Затронутые правила: ARCH-1, ARCH-3, ARCH-5, VPN-DNS-1, VPN-DNS-2, VPN-DNS-6, DESK-5, OPS-7

## Следствия

| Ресурс | Владелец механизма | Опция-интерфейс | Вкладчики |
|---|---|---|---|
| Системный резолвер | `dns-resolver` | `my.tunnel.dns.scopedZones` (объявляет `tunnel-facts` — ARCH-5, §2.3) | владельцы линков: `vpn-client` требует `scoped`-запись для своего линка и сам DNS не пишет |
| Список устройств композитора | `session-hyprland` | env-дропин UWSM `uwsm/env.d/*` (`AQ_DRM_DEVICES`) | `gpu-hybrid` — только стабильные udev-симлинки устройств |

Значения `scoped`-зон (адрес корпоративного резолвера, список зон) — **публичные
данные политики** класса C (VPN-RTE-1, SEC-2), поэтому задаются в хосте и
версионируются в git, а не вычитываются из `PUSH_REPLY` в рантайме. Это и
снимает исходную причину D6: вкладчику больше не нужно писать `resolv.conf`,
чтобы донести то, что знает только он.

Что ADR **не** меняет: ARCH-3 (фичи по-прежнему не импортируют друг друга —
вклад идёт через `config`, а не через `import`) и ARCH-5 (факт по-прежнему
определён ровно один раз — у владельца; вкладчик добавляет значение, а не
второе определение).

## Альтернативы

- **Оставить `updateResolvConf` в `vpn-client`.** Отвергнуто: плоский
  `resolv.conf` несовместим с VPN-DNS-2 (единственный upstream) и VPN-DNS-6.
- **Сделать `vpn-client` владельцем DNS целиком.** Отвергнуто: тогда владельцев
  системного резолвера двое (`dns-resolver` в M2 и `vpn-client`), что и есть
  нарушение ARCH-1, от которого уходим.
- **Передавать зоны через `specialArgs`.** Отвергнуто прямо (ARCH-8:
  `specialArgs` — не транспорт значений).
