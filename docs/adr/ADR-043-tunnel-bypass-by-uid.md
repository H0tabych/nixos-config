# ADR-43: обход туннеля по uid службы (торрент-демон), факт `my.net.bypass.users`

- Статус: принято; реализация — предусловие ROADMAP.md R5.4 (включение M2), закрывает «Открыто» в ADR-41
- Источник: решение владельца 2026-11-05 (торренты идут напрямую и в M2, ADR-41), проверка в ВМ и в сетевом пространстве имён 2026-11-06
- Решение:
  - **Признак — числовой uid системного пользователя.** Служба-клиент обхода работает под своим
    пользователем (`transmission`), uid берётся из `users.users.<имя>.uid` (явный, assertion).
  - **Маршрут** — правило политики `ip rule uidrange <uid>-<uid> lookup main` приоритетом 31999, раньше
    правил M2 (32000/32001). Маршрут и **адрес источника** выбираются при `connect()`, до метки пакета.
  - **Пропуск kill switch и обратный путь** — трафик пользователя получает метку клиента
    (`my.tunnel.killswitch.mark`) цепочкой `output` таблицы `tunnel-marks` (приоритет mangle); kill switch
    пропускает метку (VPN-KS-2), а ответы возвращаются через conntrack (`restore`) мимо строгого rpfilter.
    DNS и DoT (порты 53, 853) **не** помечаются: прямой DNS обходного пользователя получает отказ (VPN-KS-5).
  - **Факт** объявляет новая фича `net-facts` (пресет `base`): `my.net.bypass.users`. Заполняет фича-владелец
    службы (`torrent-transmission`), читает реализация слота `tunnel` (`tunnel-xray`), если она есть.
    Прежняя опция `my.tunnel.bypass.units` удалена: она нигде не читалась.
  - **Торрент-слот меняется:** `torrent-transmission` — класс N+H: системная служба `services.transmission`
    (loopback, RPC без пароля и без секретов, каталоги на томе вне снимков `/var/lib/nosnapshot/torrents`,
    группа `transmission` для пользователей capability `media`) + клиент `transmission-remote-gtk` в сессии.
- Отвергнуто:
  - **Слайс и `socket cgroupv2` в nftables.** nftables разрешает путь cgroup в id при загрузке правил, когда
    юнита (и тем более слайса пользовательской сессии) ещё нет, — загрузка падает и отрезает сеть (VPN-KS-9);
    у перезапущенного юнита каталог cgroup новый, и правило тихо перестаёт совпадать. Тот же довод уже
    записан в `tunnel-facts` при выборе метки вместо cgroup для самого клиента.
  - **Только метка в цепочке `type route hook output`.** Проверено в ВМ: сокет берёт адрес источника туннеля
    (`198.18.0.1`) при `connect()`, потом пакет переадресуется на физический интерфейс с чужим адресом —
    соединение не устанавливается. Одна метка выбирает маршрут слишком поздно.
  - **Запуск `transmission-gtk` из сессии с отдельной группой** (setgid-обёртка): процесс получает
    `AT_SECURE`, глибc отбрасывает часть окружения, ломается GTK; обёртка сама — зона повышения прав.
  - **Сетевое пространство имён клиента:** требует прав и отдельной проводки, GUI-окно — доп. проброс.
- Затронутые правила: ARCH-3, ARCH-5 (одно место факта), VPN-INT-3, VPN-KS-2, VPN-KS-5, VPN-KS-9, M2-8,
  VPN-A6, SLOT-3 (замена реализации слота `torrent` затрагивает фичу, пресет и dotfiles)
- Риски: обход — осознанное исключение из kill switch, ограниченное одним uid. RPC демона на loopback
  без пароля и без секретов (как инференс, AI-INF-1): локальный процесс, в том числе агент в режиме `online`,
  может добавить торрент и сменить настройки, но не выполнить код (скрипт по завершению выключен, служба
  заперта). Пароль отвергнут: он создал бы секрет, нужный и демону, и клиенту, ради риска «лишний торрент».
  Входящие пиры не открыты (`openPeerPorts` выключен, как и раньше). Порты 53/853 у обходного
  пользователя не работают.
- Условие пересмотра: появится метка на уровне сокета без прав приложения (cgroup-BPF `sock_create`, поддержка
  в `systemd`) — тогда обход возможен и для процесса сессии.
- Проверка: `tests/tunnel-m2.nix` (пользователь обхода выходит напрямую и при остановленном клиенте; прямой DNS
  отрезан; остальные — через туннель/отказ); на машине — M2-8 и VPN-A6 (захват на физическом интерфейсе).
