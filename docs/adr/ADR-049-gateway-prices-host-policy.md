# ADR-49: цены шлюза — из политики хоста, а не из справочника реализации

- Статус: принято 2026-11-14; реализация — ROADMAP.md R9.26. Уточняет ADR-45 (бюджеты AI-GW-6) и
  AI-GW-13 (цепочка поставок шлюза)
- Источник: находка D24. 2026-11-13 `dsh` получил `402 QUOTA: Budget exceeded: vk dsh-online budget
  exceeded: 10.0033 >= 10.0000 dollars`, хотя у провайдера списано около $5
- Причина (D24): шлюз (Bifrost 2.1.0) считает расход по справочнику цен, который сам скачивает с сайта
  поставщика (getbifrost.ai). В нём DeepSeek стоит по пиковому тарифу. DeepSeek берёт вдвое меньше вне
  пика (пик — 01–04 и 06–10 UTC по будням; выходные целиком вне пика), а понятия тарифа по часам в
  реализации нет (`off_peak` в бинарнике отсутствует). Сверка по журналам `dsh` 2026-11-06…13 (2672
  шага, кэш-попадания учтены): по пиковым ценам $9.99 — совпадает со счётчиком шлюза; по тарифу
  DeepSeek с учётом часов — $5.19 (93 % шагов вне пика). Бюджет закрылся на половине реальной суммы.
- Решение:
  - Цены облачных моделей — часть политики хоста: `my.ai.gateway.providers.<id>.prices.<модель> =
    { input; cacheRead; output; }`, USD за 1M токенов, с датой сверки по странице цен провайдера.
    Приватная часть фичи (`_llm-gateway-pricing.nix`) строит из них справочник в формате реализации;
    шлюз получает его как `file://` из хранилища и больше не скачивает справочник поставщика.
  - Сборка не проходит, если у облачной модели (роль или сквозной маршрут) нет цены: иначе её расход
    не попал бы в бюджет.
  - Для провайдера с тарифом по часам берётся тариф основного времени работы владельца; погрешность
    называется в политике хоста. DeepSeek: тариф вне пика — запрос в пиковые часы учитывается вдвое
    дешевле. Жёсткий предел остаётся у провайдера — предоплата.
  - Лимит (`budget.maxUSD = 10`, решение владельца 2026-11-06) не меняется: теперь он означает около
    $10 реальных списаний, а не $5.
- Отклонено:
  - Поднять лимит вдвое: прячет ошибку учёта; при работе в пиковые часы снова расходится.
  - Переопределения цен поверх справочника поставщика (`governance.pricing_overrides`): остаётся
    загрузка с сайта поставщика во время работы и зависимость от его данных.
  - Убрать бюджет и полагаться на предоплату: AI-GW-6 требует лимит на ключ, и у провайдера с
    постоплатой его бы не было.
- Цена и риски: цены нужно сверять со страницей провайдера при смене моделей или тарифа (как и сами
  id моделей); счётчик уже израсходованного периода не пересчитывается — разовая поправка вручную
  (docs/runbook/ai.md, «Бюджет шлюза»).
- Условие пересмотра: реализация шлюза начинает понимать тариф по часам либо провайдер его отменяет.
- Дополнение 2026-11-14 (решение владельца после R9.26): лимит шлюза на `sgms-laptop` снят — расход
  DeepSeek владелец контролирует сам, у провайдера предоплата. AI-GW-6 стал MAY (`budget.maxUSD = null`
  допустим и с облачными ролями; раздел бюджетов в конфиге шлюза тогда пустой и снимает прежний лимит).
  Цены остаются: стоимость в журнале шлюза верная, справочник поставщика не скачивается; проверка
  «у модели есть цена» действует только при заданном лимите. Пункт «Отклонено: убрать бюджет»
  пересмотрен этим решением.
- Проверка: `tests/llm-gateway.nix` — справочник из хранилища, бюджет расходуется по ценам политики и
  закрывается ответом 402; на машине — сверка счётчика шлюза со списаниями провайдера (R9.24).
