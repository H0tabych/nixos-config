# ADR-48: долгоживущая песочница тяжёлого агента — одно пространство PID на пользователя

- Статус: принято 2026-11-14; реализация — ROADMAP.md R9.25. Уточняет ADR-47 (раздел «Фоновые сессии
  тяжёлого агента») и отменяет ограничение R9.21 (AI-SBX-13: «фон между запусками не поддерживается»,
  подмена `~/.claude/daemon*` состоянием в каталоге агента)
- Источник: находка D23. Владелец 2026-11-14: после выхода из сессии Claude в неё нельзя вернуться
  (Enter в списке висит или даёт ошибку), новые сессии «не сохраняются»; решение владельца — «без
  лишних защит, пусть работает так, как задумано разработчиками»
- Причина (D23, разбор бинарника claude-code 2.1.323): реестр живых процессов Claude
  (`~/.claude/sessions/<pid>.json`) помечает запись доменом PID — машина плюс inode пространства PID.
  Запись чужого домена Claude проверить не может и считает живой навсегда (`isHeldInAnotherPidDomain`:
  `rec.pidDomain !== undefined && rec.pidDomain !== own`); чистит он только записи своего домена.
  С R9.20 каждый запуск лаунчера — своя песочница со своим пространством PID (claude там всегда pid 2),
  а `~/.claude/sessions` и `~/.claude/jobs` общие. Итог: записи прошлых окон (на машине их было 102)
  «живы», беседа выглядит открытой в другом окне; фоновые сессии гибнут по SIGKILL вместе с песочницей
  окна (`jobs/*/state.json`: «couldn't start in the background»), повторное открытие плодит копии «(2)»,
  «(3)» с новыми id; подменённые `daemon*` общие для всех окон — два окна дерутся за замок супервизора.
- Решение:
  - **Агент, чьи процессы по замыслу разработчиков живут дольше окна** (у Claude — супервизор фоновых
    сессий, реестр, `claude agents`), работает в ОДНОЙ долгоживущей песочнице на пользователя:
    транзиентный юнит `agents-<агент>.service` (`systemd-run --user`), его поднимает лаунчер при первом
    запуске; живёт до выхода из сеанса или `systemctl --user stop agents-<агент>`. Каждое окно не строит
    свою песочницу, а **входит** в эту (`agents-host enter`), поэтому все процессы агента — в одном
    пространстве PID, и реестр, фон, `claude agents`/←/Enter, `--resume`, защита «открыто в другом окне»
    работают штатно. Механизм общий (`_agents-tools-host.nix`); что нужно агенту — в адаптере
    (`longLived`: опции песочницы, действие при старте).
  - Граница — режим AI-SBX-12 (владелец, 2026-10-29): `$HOME` целиком на запись, система только на
    чтение, свои `/tmp` и `/run` (нет сокетов сеанса, шины, ключей шлюза, `/run/secrets`, сокета
    контейнеров), сеть — pasta + nftables `online` (AI-SBX-5). Песочница **без проекта**: проектных
    привязок (метаданные git только на чтение, свой `.direnv`, `.envrc` только на чтение — AI-SBX-7)
    у долгоживущего агента нет — «без лишних защит»; при `$HOME` на запись они и так были оградой, а не
    границей (тот же агент мог переписать `~/.config/git`). Отчёт лаунчера о git после окна остаётся.
  - Вход — два шага `nsenter` (ограничение ядра, по исходникам `setns`): сеть принадлежит пространству
    пользователя pasta, остальные пространства — вложенному bwrap; из вложенного прав над родительским
    нет. Рабочий каталог задаёт `env -C` уже внутри (`nsenter --wd` открывает каталог в пространстве
    монтирования хоста — путь мимо корня). Окружение — ровно перечень AI-SBX-3 (`agents-sandbox-exec
    --print-env`, потоком, не через argv); унаследованные дескрипторы, кроме терминала, закрываются.
    pid процесса 1 песочницы ищется по дереву юнита и сверяется с id пространства PID из `bwrap --info-fd`
    («child-pid» bwrap не годится: pasta запускает команду в своём пространстве PID — ПРОВЕРЕНО в ВМ).
  - **Сброс реестра живых процессов при старте песочницы** (адаптер claude): inode пространства PID
    новый у каждого запуска песочницы, а в момент её старта процессов claude нет нигде (остановка
    песочницы гасит всё её пространство PID). Поэтому все записи `~/.claude/sessions/<pid>.*` мертвы и
    удаляются — как их удалил бы сам Claude. Беседы (`projects/`), фоновые сессии (`jobs/`), супервизор
    (`daemon*`) штатные, в настоящем `~/.claude`; подмена `daemon*` (R9.21) снята.
- Отклонено:
  - Песочница на запуск со своим реестром: беседа возвращается через `/resume`, но фон умирает с окном,
    `claude agents` прошлых сессий не видит, а два окна открывают одну беседу без предупреждения (порча
    истории) — защита Claude «открыто в другом окне» работает только в общем реестре.
  - Песочница без своего пространства PID: процессы агента видели бы процессы хоста, а
    `/proc/<pid>/root` процесса того же пользователя — выход в файловую систему хоста.
  - Привязки метаданных git на каждый вход (`nsenter` + `mount`): сложность ради ограды, которую
    `$HOME` на запись всё равно обходит; владелец — «без лишних защит».
- Цена и риски:
  - Проекты вне `$HOME` долгоживущему агенту недоступны (лаунчер отказывает с объяснением).
  - Адреса хоста для правил D21 снимаются при старте песочницы: смена сети во время её жизни не
    попадает в правила до перезапуска юнита (`systemctl --user restart agents-claude` — с остановкой фона).
  - Новое поколение системы песочница подхватывает при следующем старте юнита (после выхода из сеанса
    или ручного перезапуска): активация Home Manager транзиентный юнит не трогает — фон не теряется.
  - Сеанс без логина пользователя (su, ssh) поднимает песочницу тем же менеджером пользователя.
- Условие пересмотра: Claude меняет устройство реестра (домен PID, путь `sessions`) — тогда сброс в
  адаптере пересматривается; либо появляется агент с долгоживущими процессами и режимом `offline`.
- Проверка: `tests/agent-network.nix` (два окна — одно пространство PID; фоновый процесс переживает
  окно; сброс реестра; проект вне `$HOME` — отказ; остановка юнита гасит всё),
  `tests/agent-sandbox.nix` (песочница без проекта, `--info-file`, `--print-env`); на машине — AI-A20.
