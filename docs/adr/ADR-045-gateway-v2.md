# ADR-45: шлюз v2 — системная служба, прямые провайдеры, сквозной маршрут, MCP-шлюз

- Статус: принято; реализация — ROADMAP.md R9.16, R9.20. Дополняет ADR-21
- Источник: решение владельца 2026-11-06 (облако — платный прямой API, агрегаторы убираются; GitHub
  и Jira доступны всем агентам); аудит 2026-11-06 (D17, D18, D19)
- Решение:
  - **Шлюз — системная служба на пользователя** (`DynamicUser`, учётные данные через
    `LoadCredential`, `ProtectHome`, `ProtectSystem=strict`). Секреты принадлежат root; пользователю
    (и значит агенту) читаются только файлы его собственных ключей доступа. Это закрывает чтение
    секретов шлюза из песочницы, возвращает автоматический перезапуск при смене секрета и ограничивает
    права юнита (AI-GW-13). Порт по формуле AI-GW-1 сохраняется.
  - **Только прямые провайдеры.** Агрегаторы не используются. Провайдеры объявляются нейтральными id
    (`my.ai.gateway.providers.<id>`: тип и список собственных моделей), секрет называется по id
    (`ai.gateway.providerKey.<id>`), имён вендоров в ключах нет (SEC-3). Облачные роли
    ссылаются на id провайдера и модель.
  - **Сквозной маршрут (AI-ROLE-5).** Агент, привязанный к семейству моделей, ходит по собственным
    идентификаторам моделей своего провайдера (для `dsh` — каталог выбора модели его интерфейса).
    Шлюз маршрутизирует их правилом по явному перечню `nativeModels` провайдера, целевая модель не
    переопределяется. Роли (раздел 4) остаются для агентов и редакторов, не привязанных к провайдеру.
  - **Ключи доступа — по паре «роль агента × режим».** Служба генерирует их при старте и хранит в своём
    состоянии. Ключ режима `offline` допускает только локальный бэкенд и не допускает инструменты.
    Права запрещены по умолчанию (провайдеры и инструменты перечисляются явно). На ключи — бюджеты
    (AI-GW-6). Ключ расходов провайдера хранится в sops, ключи доступа — нет.
  - **MCP-шлюз для инструментов с секретами.** Серверы, которым нужен токен (GitHub — только чтение,
    Jira), запускает шлюз под своим пользователем; агент получает только свой ключ доступа и список
    разрешённых инструментов. Токены — в sops, по нейтральным id (`ai.gateway.toolKey.<id>`). Локальные
    серверы без секретов (LSP, браузер, документация) по-прежнему запускаются внутри песочницы по
    stdio (AI-CTX-4).
- Отвергнуто:
  - **Пользовательский юнит с секретами в `/run/secrets` с владельцем-пользователем** (было): секреты
    читаются любым процессом пользователя, включая агента.
  - **Один ключ доступа на пользователя** (было): нельзя ограничить роль, режим и инструменты.
  - **Бесплатные тарифы прямых провайдеров:** лимиты и состав нестабильны, запросы обычно идут в
    обучение; для рабочего кода недопустимо (AI-SEC-9).
  - **Агрегатор как основной канал:** лишний посредник между приватным кодом и провайдером.
  - **Подмена имени модели в профиле агента** (`cordis.patch.yml` с именем роли): ломала каталог
    выбора модели у `dsh`, а файл — место сохранения его интерфейса.
- Затронутые правила: AI-GW-1, AI-GW-2, AI-GW-3, AI-GW-4, AI-GW-6, AI-GW-7, AI-GW-13, новое AI-GW-14,
  AI-ROLE-2, новое AI-ROLE-5, AI-AGT-6, AI-CTX-4, AI-OPS-6, AI-A6, AI-A14, SEC-3, SEC-4, USER-7
- Риски:
  - API провайдера DeepSeek не обещает отсутствия обучения на запросах (условия API от 2026-04), политика
    конфиденциальности называет обучение целью, данные, вероятно, хранятся в КНР. Поэтому рабочие
    корни — `offline` по умолчанию (ADR-44), облако — только явным флагом (AI-SEC-9).
  - Расширения протокола `dsh` (режим рассуждения и его подписи, правка набора инструментов посреди
    диалога, загрузка файлов) могут теряться при преобразовании шлюзом: приёмка AI-A17; запасной
    вариант — явный список моделей в конфиге `dsh` без расширений (Приложение P, P.5).
  - Служба запускает серверы инструментов: их пакеты — критичное звено цепочки поставок (AI-GW-13).
  - В режиме M1 системная служба не получает переменные прокси из сессии: прокси задаётся в её конфиге
    из `my.tunnel.local.http` (одно место, NET-10).
- Условие пересмотра: провайдер с письменным обязательством «без обучения и хранения» в условиях API;
  либо шлюз, поддерживающий пользовательские права на сквозной маршрут без перечня.
- Проверка: ВМ-тест (служба стартует без ключей — AI-A14; ключ `offline` не достаёт облачную роль;
  инструменты запрещены по умолчанию), вычисление отрендеренного конфига; на машине — запросы
  по матрице ключей, AI-A6, AI-A9, AI-A17.
