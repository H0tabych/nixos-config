# ADR-51: агенты в родных протоколах — dsh ходит к DeepSeek напрямую, облако из шлюза убрано

- Статус: принято 2026-11-25 (решение владельца); реализация — ROADMAP.md R9.28: `modules/ai/agents-keys.nix`,
  адаптер `_agents-tools-dsh.nix`, политика `_agents-tools-dsh-policy.nix`, шлюз (`llm-gateway.nix`,
  `_llm-gateway-*.nix`), хост `sgms-laptop.nix`. Заменяет в ADR-45 облачных провайдеров, роли и сквозной
  маршрут (AI-GW-2, AI-GW-5, AI-GW-6, AI-ROLE-5); упраздняет ADR-49 (цены и бюджеты шлюза).
- Источник: жалоба владельца — `dsh` работает «кардинально хуже» `claude`, чем не объяснить разницей
  моделей; хост выбирает модель за него (роли `cost-/strong-autonomous`); шлюз преобразует форматы.
- Находки (по исходникам Bifrost `transports/v2.1.0`, ПРОВЕРЕНО чтением; живой запрос — см. «Проверка»):
  - `dsh` говорит только на **Anthropic Messages** (`llm-deepseek`, «Configuration accepts Messages
    only»); родной endpoint — `https://api.deepseek.com/anthropic`, `/v1/messages`, `/v1/files`.
  - Через шлюз запрос шёл так: Messages → `ToBifrostResponsesRequest` → `ToChatRequest()` → **OpenAI
    chat-endpoint DeepSeek** (`use_anthropic_endpoints` в нашем конфиге не задан, умолчание — выключено).
    Три преобразования; поля `output_config`, подписи thinking-блоков и Files API не имеют образа в
    OpenAI chat-схеме.
  - Шим `applyDeepSeekThinkingCompatibility` (`core/providers/deepseek/deepseek.go`) **молча выключает
    рассуждение**, если в истории есть ход ассистента с вызовом инструмента без повторяемого
    `Reasoning` (`ReasoningDetails` на провод не идёт); комментарий в коде сам называет это тихой потерей.
    Для агента, где почти каждый ход — вызов инструмента, это прямая деградация качества.
  - Политика Nix отключала родные поиск и загрузку страниц DeepSeek, потому что в `DEEPSEEK_API_KEY`
    лежал ключ шлюза, а не провайдера.
  - Роли шлюза означали, что модель выбирает хост; владелец выбирает её сам в интерфейсе агента.
- Решение:
  - Каждый агент ходит к своей модели **в родном протоколе, без посредника**: `claude` и `codex` — по
    подписке (как и раньше, AI-GW-11), `dsh` — **напрямую** на `api.deepseek.com/anthropic`
    (`DEEPSEEK_BASE_URL` не задаётся).
  - Ключ провайдера — секрет из sops пользователя (`my.ai.agentKeys.dsh.sopsKey`, имя в sops прежнее
    `ai.gateway.providerKey.primary`), фича `agents-keys` отдаёт его файлом 0400 в `/run/secrets`; лаунчер
    читает файл снаружи песочницы и передаёт **значением** в `DEEPSEEK_API_KEY` (`--pass-env`, AI-SBX-3).
  - Из шлюза убраны облачные провайдеры, облачные роли, сквозной маршрут, бюджеты, цены и sops-секреты
    провайдеров. Остались: локальные роли (Ollama) и MCP-шлюз (`jira`, `web-search`); ключи доступа по
    паре «агент × режим» нужны для инструментов. Справочник цен моделей Bifrost — пустой файл из хранилища.
  - Адаптерный признак `subscription` → `cloudOnly`: агент без облака не работает; `dsh`, как `claude` и
    `codex`, в `offline` не запускается.
  - Политика `dsh`: родные `web-search-deepseek`, `web-deepseek-api`, `tool-web` включены; телеметрия,
    выгрузка журнала сессии и перечня пакетов, менеджер плагинов — выключены, как раньше.
  - Модель и усилие рассуждения выбирает владелец в интерфейсе `dsh`; хост умолчаний не задаёт.
- Цена (принята): агент видит ключ провайдера (потолок убытка — предоплата у DeepSeek; прежний лимит
  шлюза владелец снял 2026-11-14); расход не считает шлюз — смотреть счёт у провайдера и журнал самого
  `dsh`; `dsh` не работает в `offline` (локальной модели в `dsh` и раньше не было).
- Отклонено: прозрачный прокси без преобразований, держащий ключ у root, — формат не меняется, но это
  новая деталь для сопровождения, учёта он тоже не даёт; включить `use_anthropic_endpoints` — всё равно
  два преобразования через внутреннюю схему и шим; оставить шлюз для `dsh` и «чинить» его — лишний
  слой между агентом и моделью без выгоды.
- Проверка: живой запрос через прежний шлюз (история с `tool_use` без повторяемого рассуждения) против
  прямого — ПРОВЕРИТЬ при желании; вывод ADR опирается на исходники. Критерий приёмки — AI-A17
  (ходит напрямую, без обращений к шлюзу; рассуждение и инструменты идут без преобразований). Сравнение
  качества `dsh` до и после — набор 8.2 (R9.24).
- Применение: пересборка `just build`/`test`/`boot` делает владелец; перед ней убедиться, что строка
  `ai.gateway.providerKey.primary` есть в `secrets/users/<user>.yaml` (она там уже есть).
