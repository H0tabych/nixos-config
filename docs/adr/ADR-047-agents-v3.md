# ADR-47: подсистема агентов v3 — сеть сокетами хоста, режимы вместо ролей, единая документация

- Статус: принято 2026-11-11; реализация — ROADMAP.md R9.20–R9.24. Частично заменяет ADR-44 (сетевые
  режимы, режим по умолчанию, корни рабочих деревьев и маркер `.ai/offline`) и ADR-46 (память
  выключена, запрет `CLAUDE.md`, «только этот список MCP», контролируемый агент `OpenCode`). Остальное
  в ADR-44…46 действует
- Источник: решения владельца Р1–Р13 (2026-11-08…11); находки D21, D22 (ROADMAP §8). 2026-11-08 владелец
  потребовал исправить первой невозможность работы с проектами за корпоративным VPN: до постоянного
  решения изоляция выключена (`isolation = false`)
- Решения владельца (номера используются в тексте ниже; Р5 заменено Р10):
  - Р1 — память агентов вернуть; Р2 — файлы агентов в проекте допустимы, без зоопарка файлов;
    Р3 — единая документация для агентов; Р4 — переработка подсистемы целиком, без костылей;
  - Р6 — RAG только по замеру; Р7 — эффективность агента выше наших правил, правила — по назначению;
  - Р8 — контролируемый агент — режим автономного (`--controlled`), `aider` удаляется без замены,
    агентов два; Р9 — `CLAUDE.md` = импорт `AGENTS.md` + специфика;
  - Р10 — память штатная, важное — в документах; Р11 — облако по умолчанию разрешено, исключения
    назовёт владелец; Р12 — все VPN хоста доступны всем проектам;
  - Р13 — в `online` агент видит сеть как пользователь (loopback хоста, LAN), D21 исправить.
- Решение:
  - **Граница безопасности — песочница лаунчера**, одна для всех агентов (AI-SBX-1…3, 6). Встроенные
    песочницы и списки разрешений агентов — удобство режима `controlled`, не граница (AI-SBX-8).
  - **Агент работает так, как задумали его разработчики** (память, навыки, плагины, подключения
    аккаунта, фоновые сессии): мы задаём границу (файлы, сеть) и минимальную политику, без которой
    нельзя. Каждое ограничение имеет названную цену и обоснование (Р7, AI-AGT-9).
  - **Агентов два:** тяжёлый (подписка, мимо шлюза — AI-GW-11) и альтернативный (другое семейство
    моделей, сквозной маршрут шлюза — AI-ROLE-5). Контролируемый агент как отдельный продукт не нужен:
    это **режим** автономного агента (`--controlled`: показ изменений, подтверждение правок и команд).
    `aider` удаляется без замены, `OpenCode` не вводится (Р8).
  - **Адаптеры агентов.** Всё знание о конкретном агенте (пакет, доступ к домашнему каталогу, каталоги
    приложения, модель, политика, аргументы режимов, формат MCP, публикуемые порты, известные файлы в
    проекте) — в одном адаптере на агента (слой Nix); лаунчер общий и конкретных агентов не знает.
    Единственная точка входа остаётся прежней (AI-AGT-4).
  - **Политика уровня 0 передаётся флагами запуска**, а не файлами: Nix не пишет конфиги приложений
    (DOT-3). Пользовательские настройки приложения (уровень 1) Nix не трогает.
  - **Сеть агента v3.** Лаунчер запускает песочницу в своём пространстве имён сети и пользователя,
    созданном пользовательским сетевым стеком (`pasta`), с правилами `nftables`, которые загружает
    охранник до старта агента; агент прав в этом пространстве не имеет и правил не меняет; сбой любого
    шага — агент не стартует (AI-SBX-6). Соединения агента выходят **сокетами хоста**: по маршрутам
    хоста (туннель, корпоративный VPN, переключатель маршрута NET-13) и через резолвер хоста
    (корпоративные зоны). Подходит любой протокол (SSH, БД, ICMP), а не только HTTP. Отдельное
    пространство имён сохраняется ради режима `offline` и изоляции абстрактных сокетов хоста
    (графическая сессия, шины).
    - `online` (по умолчанию) — **сеть как у пользователя**: интернет, все VPN хоста, службы loopback
      хоста (БД и сервисы контейнеров, серверы разработки, IDE, инференс), адреса хоста, LAN (Р13).
      Закрыты: абстрактные сокеты хоста, сокеты сессии, системная шина.
    - `offline` — шлюз, DNS и сети VPN хоста; всё остальное, включая адреса самого хоста, закрыто.
    - **Сети VPN** = маршруты через линки корпоративных VPN (`my.tunnel.dns.scopedZones.*.link`) в
      момент запуска; проект к VPN не привязывается, все VPN доступны всем проектам (Р12).
    - Проброс входящих задаётся явно (флаг `--publish`, веб-интерфейс агента — только на `127.0.0.1`
      хоста).
  - **Облако по умолчанию разрешено** (Р11). Исключения — корни в `dotfiles/ai/roots.toml`
    (`cloud = "deny"`) и флаг `--offline` на один запуск. Маркер `.ai/offline` удаляется: политику
    задаёт владелец, проект её не меняет (AI-SEC-5). Агент по подписке в `offline` не запускается;
    альтернативный агент в `offline` работает только на локальных ролях.
  - **Удаляются:** мосты `socat` (`agents-net host/inside`, `/run/agents-bridge`), прокси-переменные в
    режиме M2, `all_proxy=` для альтернативного агента, переключатель `isolation`, режим «рабочие
    корни по умолчанию `offline`» (AI-SEC-6 в старой редакции). Правило «HTTP-вход туннеля не
    открывает частные адреса и `localhost`» остаётся — оно защищает сам вход в режиме M1.
  - **Файловая граница** (ADR-44) сохраняется: корень из разрешённого, окружение с нуля, ключ шлюза
    значением, метаданные git только на чтение, работа на месте. Добавляются: свой `resolv.conf`
    (адрес пересылки DNS), `~/.config/ai` на чтение, каталоги приложения агента (память, сессии) на
    запись — из адаптера.
  - **Память агентов штатная** (Р10; отменяет выключение из ADR-46): у тяжёлого агента — автопамять в
    его каталоге приложения, у альтернативного встроенной памяти нет и не добавляется. Общей памяти и
    MCP-памяти нет; всё важное — в контекстных документах.
  - **Фоновые сессии тяжёлого агента** (супервизор, переживающий закрытие терминала) работают как
    отдельная долгоживущая песочница с той же политикой; интерактивные запуски подключаются к ней
    через общий каталог сокетов. ПРОВЕРИТЬ в R9.21: обнаружение супервизора между пространствами
    имён; если нельзя — записанное ограничение и решение владельца (AI-A20).
  - **Единая документация** (Р3, Р9; отменяет запрет `CLAUDE.md` из ADR-46). В своих проектах:
    `AGENTS.md` — канон; `CLAUDE.md` — только импорт `AGENTS.md` и специфика тяжёлого агента; навыки —
    `.agents/skills/<имя>/SKILL.md`, для агента, читающего `.claude/skills`, — симлинк; личное —
    `AGENTS.local.md`. Читают оба агента штатно: тяжёлый — через настройку источников инструкций
    (`CLAUDE.md`, затем `AGENTS.md` каталога), альтернативный — оба файла в каждом каталоге.
    **Чужие (командные) репозитории не переписываются:** агенты читают в них то, что умеют нативно.
    Глобальное — в `dotfiles/ai/`; ссылки на стандартные пути агентов (`~/.agents`,
    `~/.claude/CLAUDE.md`, `~/.claude/skills`) делает единый механизм ссылок dotfiles (DOT-4, DOT-8).
    Инициализация проекта — навык `agents-init`.
  - **Файлы агентов в проекте допустимы** (Р2, Р7): правила — по назначению (знание в общем формате;
    восстанавливаемое состояние — в каталог состояния; нужное агенту в его формате — допускать и
    учитывать в адаптере), а не списками имён. Обнаружение — отчёт лаунчера после сессии (новые
    неотслеживаемые файлы с пометкой «файл агента: причина», проверка документов своего проекта).
  - **MCP.** Единый список `dotfiles/ai/mcp-servers.toml` — для серверов, общих для агентов; локальные
    без секретов — в песочнице, с секретами и удалённые — через MCP-шлюз (AI-GW-14). Строгий режим
    «только этот список» **не используется**: он отключил бы плагины и подключения аккаунта тяжёлого
    агента; серверы проекта подключаются только с подтверждением (AI-SBX-9). Ключ шлюза у тяжёлого
    агента — только для инструментов (AI-SEC-2).
  - **RAG не строится** (Р6): L0–L3 без изменений; гейт 8.3 расширяется на документы, решение — по
    замеру набора 8.2 в обоих режимах и у обоих агентов (R9.24).
- Отвергнуто:
  - **Выход только через HTTP-вход туннеля** (R9.17): режет частные адреса, не покрывает SSH, БД и
    DNS корпоративных зон (D22); единственный поддерживаемый протокол — HTTP.
  - **Сеть хоста без отдельного пространства имён:** нет режима `offline`, абстрактные сокеты хоста
    (графическая сессия, шины) доступны агенту.
  - **veth и NAT, настраиваемые от root:** привилегированный код и постоянная настройка хоста ради
    того, что делает непривилегированный стек; второй набор маршрутов, дублирующий политику туннеля.
  - **Встроенная песочница тяжёлого агента как граница:** только прокси-сеть, а не пространство имён;
    остаётся удобством режима `controlled`.
  - **`OpenCode`, `Vibe`, `Hermes`, `Codex`, `Crush`, `Goose` как контролируемый агент:** режим
    автономного агента решает задачу без третьего продукта в сопровождении (Р8).
  - **Общая память агентов:** собственная разработка без гейта 8.3 (AI-CTX-6); штатная память
    каждого агента не мешает (Р10).
  - **«Рабочие проекты по умолчанию `offline`»:** расходится с практикой владельца; исключения
    задаются данными (Р11).
  - **Привязка проектов к VPN:** все VPN хоста доступны всем проектам, различать нечем (Р12).
  - **Закрытый loopback хоста в `online`:** ломает работу с БД и сервисами контейнеров на
    `localhost` (Р13); цена — закрыть D21.
  - **Строгий режим MCP:** см. выше.
  - **Переопределение источников инструкций альтернативного агента:** в командных репозиториях
    бывает только `CLAUDE.md`; умолчание разработчиков сохраняется.
- Затронутые правила: AI-AGT-1, AI-AGT-3, AI-AGT-4, AI-AGT-7, AI-AGT-8, новое AI-AGT-9, AI-SBX-2,
  AI-SBX-3, AI-SBX-5, AI-SBX-6, AI-SBX-8, AI-SBX-9, AI-SBX-11, AI-SBX-12, новое AI-SBX-13, AI-SEC-4,
  AI-SEC-5, AI-SEC-6, AI-SEC-9, AI-CTX-3, AI-CTX-4, AI-GW-11, AI-A7, AI-A8, AI-A10, AI-A12, AI-A15,
  AI-A16, AI-A18, новые AI-A19, AI-A20, DOT-4, DOT-8, VPN-MOD-6, VPN-MOD-10, VPN-INT-1, STR-1,
  ADR-31
- Риски:
  - В `online` агент видит loopback хоста: любая служба без аутентификации доступна ему как
    пользователю. Предусловие возврата изоляции — закрыть D21 (RPC торрентов; её uid обходит туннель
    и kill switch) в R9.20: владелец `media` объявляет порт RPC фактом `my.net.sensitiveLoopbackPorts`, правила
    сетевого стека агентов его закрывают (решение 2026-11-12: без пароля и сокета — клиент не умеет unix-сокет).
  - Облако по умолчанию: проекты с ограничениями работодателя нужно внести в `roots.toml` до работы
    с ними (AI-SEC-9); без записи агент увидит их как обычные.
  - Сети VPN определяются при запуске: VPN, поднятый позже, не виден в `offline` до перезапуска
    агента.
  - Пересылка сокетов хоста зависит от пользовательских пространств имён (AI-SBX-11) и от
    корректности правил `nftables` внутри пространства стека. ПРОВЕРИТЬ в ВМ: загрузка правил, отображение
    uid в режиме запуска команды, IPv6, UDP для локальных служб.
  - Идентификатор значения настройки источников инструкций тяжёлого агента найден в бинарнике
    версии 2.1.317; путь ключа в `--settings` — ПРОВЕРИТЬ в R9.22.
  - Фоновые сессии тяжёлого агента: механизм обнаружения супервизора между пространствами имён
    не подтверждён (см. выше).
- Условие пересмотра: пользовательский сетевой стек перестаёт давать выход сокетами хоста либо
  перестаёт работать в непривилегированном режиме; либо замер 8.2 показывает, что граница снижает
  успешность задач ощутимо; либо владелец вводит агента, не умещающегося в два режима.
- Проверка: AI-A7, AI-A8 (с возвратом изоляции), AI-A12 (оба режима), AI-A15, AI-A18 (v3),
  AI-A19, AI-A20; ВМ-тесты `tests/agent-network.nix`, `tests/agent-sandbox.nix`,
  `tests/llm-gateway.nix`; на машине — БД, SSH и HTTPS проекта за VPN по имени и по адресу, БД
  контейнера на `localhost`.
