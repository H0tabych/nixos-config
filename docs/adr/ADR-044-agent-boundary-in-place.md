# ADR-44: граница агентов v2 — корень из разрешённого, работа на месте, сеть по режимам

- Статус: принято; реализация — ROADMAP.md R9.1, R9.14, R9.15, R9.17. Заменяет в ADR-22 часть про
  открытый домашний каталог (дополняется перечнем потерь) и отменяет клон из AI-SBX-7
- Источник: решение владельца 2026-11-06 (агенты работают в текущем проекте, ветки и коммиты — дело
  человека, коммиты агентам разрешены; роль `claude` остаётся с открытым `$HOME`); аудит песочницы
  изнутри 2026-11-06 (D16, D17)
- Решение:
  - **Корень песочницы собирается из разрешённого, а не из `/` с масками.** Только чтение: хранилище
    пакетов, `/etc`, `/run/current-system`, `/bin/sh`, `/usr/bin/env`, сокет демона сборки. Заново:
    `/dev`, `/proc`, `/tmp` и `/run` (пустой, свой `XDG_RUNTIME_DIR`). Каталог сессии пользователя,
    системная шина, `/run/secrets*` и любые новые сокеты хоста не видны без перечня запретов.
  - **`~/.config` — белый список** (`machine.d`, `ai`, `git`, `direnv`, каталог самой роли). Остальное
    скрыто. Рабочая копия dotfiles и база разрешений direnv — только чтение. У каждой роли свои
    `XDG_CACHE/STATE/DATA` в каталоге состояния.
  - **Работа на месте.** Каталог проекта — корень git-дерева или текущий каталог, на запись. Из git
    только на чтение: `config`, `config.worktree`, `hooks` (и путь `core.hooksPath`, если он внутри
    дерева), `info`, конфиги и хуки подмодулей, `.git`-файлы связанных деревьев и подмодулей,
    `.envrc`. Общий git-каталог привязан к самому себе (иначе `mv .git` обходит защиту). Объекты,
    ссылки и индекс на запись: **агент коммитит**. `.direnv` у агента свой (в каталоге состояния).
    Лаунчер после сессии сообщает о ссылках, сдвинутых вне текущей ветки, флагах индекса
    (`skip-worktree`, `assume-unchanged`), `refs/replace`, новых вложенных `.git` и изменённых
    игнорируемых файлах.
  - **Сеть — отдельное пространство имён.** Режим `online`: только шлюз, поиск и HTTP-вход туннеля как
    единственный выход (адрес из `my.tunnel.local.http`). Режим `offline`: только шлюз со своим
    ограниченным ключом. Мосты поднимает лаунчер. Режим по умолчанию задают корни рабочих деревьев в
    `dotfiles/ai/` и маркер `.ai/offline`; облако в рабочих корнях включается флагом `--online` на
    запуск (AI-SBX-5, AI-SEC-6). Роль `claude` в `offline` не запускается: подписка — это облако.
  - **Доверие демону сборки.** `trusted-users` без `@wheel`: доверенный пользователь равносилен
    root, а сокет демона доступен из песочницы.
  - **`--home-rw` (AI-SBX-12) сохраняется для `claude`.** Риск принят владельцем. Перечень потерь
    дополнен: ключ расшифровки секретов хоста, автозапуск и конфиги оболочки/сессии, глобальный
    конфиг git, `~/.ssh/authorized_keys`, профили браузера и почты. Закрываются побег через сокеты
    сессии (корень выше) и доступ к секретам шлюза; остальное — принятый риск.
- Отвергнуто:
  - **Клон проекта на отдельной ветке (прежний AI-SBX-7).** Человек должен видеть изменения на месте;
    защита от push не держалась: сборочная оболочка проекта переустанавливала `core.hooksPath`.
  - **Связанный `git worktree`.** Общий `.git` с репозиторием пользователя; без защиты метаданных не
    лучше работы на месте.
  - **Перечень масок поверх `--ro-bind / /`.** Так возникли дыры: любой новый сокет хоста снова виден.
  - **Отдельный пользователь-песочница** (ARCH-17: пользователи — данные).
  - **`--new-session`:** ломает терминальные интерфейсы; TIOCSTI закрыт параметром ядра
    `dev.tty.legacy_tiocsti=0`, который фиксируется в R9.1.
- Затронутые правила: AI-SBX-1, AI-SBX-2, AI-SBX-5, AI-SBX-7, AI-SBX-12, AI-SEC-3, AI-SEC-6, AI-AGT-1,
  AI-A7, AI-A8, AI-A12, AI-A18, SEC-1, DEV-6
- Риски:
  - Объекты, ссылки и индекс git остаются на запись: агент может удалить ветки и reflog или скрыть
    правки флагами индекса. Смягчение — отчёт лаунчера и ежедневные снимки `home`.
  - Игнорируемые файлы (`.gitignore`) агент меняет без следа в `git status`.
  - Демон сборки остаётся каналом выхода (загрузки с фиксированным хэшем) даже в `offline`;
    маскировка сокета в этом режиме — ПРОВЕРИТЬ в R9.17.
  - Для `claude` в `--home-rw` проверки «ключи и репозиторий конфигурации недоступны» не применимы.
  - Копии репозитория конфигурации с зашифрованными секретами лежат в хранилище пакетов и читаемы
    всем; граница — недоступность ключа расшифровки, а не копий.
- Условие пересмотра: появление в git режима «репозиторий только для добавления» либо метки доступа
  на уровне ссылок; либо решение владельца убрать `--home-rw` (тогда — `--add-dir` для дополнительных
  деревьев).
- Проверка: `tests/agent-sandbox.nix` на реалистичных фикстурах (секрет 0400 владельца, сокеты
  пользовательской сессии, системная шина, ключ расшифровки, профиль браузера — для каждой роли),
  `tests/agent-network.nix`; на машине — AI-A7, AI-A8, AI-A18 по `docs/runbook/ai.md`.
