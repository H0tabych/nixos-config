# nixos-config — инструкции для ассистента

## Что это

Декларативная конфигурация NixOS для одного ноутбука. Строится **с нуля** по документам; старая система — только источник данных для миграции.

- Железо: ASUS TUF Gaming F15 (i5-10300H, GTX 1650 с 4 ГБ VRAM, гибридная графика без MUX, 24 ГБ RAM, NVMe 512 ГБ). Хост `sgms-laptop`, пользователь `sgm`.
- Назначение: (1) работа тимлидом и разработчиком — python, sql, c/c++, rust, офисные приложения; (2) игры и видео; (3) агенты и нейросети.

## Документы

Лежат в `docs/architecture/` и `docs/hosts/`. **Целиком не читай** — они большие. Ищи по ID правила:

```
grep -n "STO-4" docs/architecture/*.md
```

и читай найденный раздел, а не весь файл.

| Файл | Что в нём | Префиксы ID |
|---|---|---|
| `ARCHITECTURE.md` | нормативная архитектура; критерии приёмки A1–A18 | ARCH, STO, SEC, NET, DESK, DOT, OPS, HOST, FEAT, SLOT, USER, DEV, APP |
| `STRUCTURE.md` | куда что класть в репозитории; проверки C1–C11 | STR |
| `VPN_SUBSYSTEM.md` | туннель, DNS, kill switch | VPN |
| `AI_SUBSYSTEM.md` | инференс, шлюз, агенты | AI |
| `ROADMAP.md` | пошаговый план; шаги `R<этап>.<n>`, Gate'ы `G<n>` | R, G, W |
| `docs/hosts/sgms-laptop.md` | факты железа; значения с ⚠ не подтверждены | — |

**Приоритет при расхождении:** ARCHITECTURE > STRUCTURE > VPN/AI > ROADMAP. Расхождение не разрешай молча: остановись, назови оба места и предложи правку документа.

## Архитектура каркаса

Паттерн — "dendritic-lite" (ADR-001): `flake.nix` подключает `flake-parts` и
`import-tree`, который рекурсивно импортирует **все** `.nix`-файлы под `modules/`
как flake-parts-модули — отдельного списка импортов в репозитории нет. Файл без
ведущего `_` — это фича (`flake.modules.nixos.<имя>`/`.homeManager.<имя>`) или
часть `core/`; состав фич в хосте задают только `presets/` и `hosts/` — на этом
этапе их ещё нет (появятся в ROADMAP R2.x).

Dotfiles — отдельный репозиторий, подключён как `flake = false`-input `dotfiles`;
конфиги приложений туда, а не сюда (ARCH-15, DOT-3).

## Жёсткие правила

1. **Секреты.** Никогда не читай, не печатай и не коммить значения секретов, ключи age/SSH, содержимое `secrets/`. В примерах только плейсхолдеры `<…>`. Не проси пользователя прислать значение в чат.
2. **Опасные команды не запускай**, даже если среда позволяет: `sudo`, `nixos-rebuild`, `nixos-install`, `disko`, `btrfs`, `cryptsetup`, `mkfs`, `dd`, `git push`, сборка мусора, удаление. Покажи команду, объясни, что она делает и как откатить; запускает пользователь (ROADMAP W10).
3. **Структура.** Путь = адрес: `modules/<домен>/<фича>.nix`, ровно два уровня, имя файла = имя фичи (STR-2, STR-4). Фича не импортирует фичу (ARCH-3). Нет `lib/`, `overlays/`, `pkgs/`, `common/` (ARCH-11). Имён пользователей в путях и именах фич нет (ARCH-17). Конфиги приложений — только в репозитории dotfiles (ARCH-15).
4. **Не выдумывай.** Имена опций, пакетов и версий проверяй (`nix eval`, `nix search`, search.nixos.org), а не пиши по памяти. Канал — стабильный 26.05. Не уверен — оставь пометку `ПРОВЕРИТЬ`; существующие пометки не убирай без проверки.
5. **Один шаг — одна сессия.** Работай по шагу ROADMAP (`R<этап>.<n>`). Пока Gate предыдущего этапа не пройден, шаги следующего не предлагай. Галочки в ROADMAP ставит пользователь.
6. **Сначала план.** Перед изменением нескольких файлов покажи список файлов и что изменишь; дождись согласия.

## Как работать

- Разработка — внутри `nix develop` (`.envrc` делает это автоматически через direnv).
- Проверка перед коммитом: `just check` (= `nix fmt` + `nix flake check`); структурные
  проверки отдельно — `bash scripts/check-structure.sh`; скан секретов отдельно —
  `bash scripts/check-secrets.sh` (обёртка над `gitleaks detect`).
- Секрет — только `just sops-edit <файл>`; ключи получателей — `just sops-rekey`.
- Применение на машине — только по OPS-3: `just build <host>` → `nvd diff` →
  `just test <host>` → `just boot <host>`. Это делает пользователь, не ассистент
  (правило 2 выше).
- `just add-host`/`add-user`/`new-feature` и `just bootstrap`/`dotfiles-clone` —
  заготовки-стабы (`scripts/new-feature.sh` ещё не создан); не предлагать их как
  готовые команды до соответствующего шага ROADMAP.
- Коммиты маленькие, по шагу; сообщение начинается с ID шага: `R1.2: каркас core/`.
- Ответы на русском, коротко; код и идентификаторы — как в документах.
- Нужен новый файл — назови путь по STRUCTURE.md, класс (`nixos` / `homeManager`), пресет-владелец и список затрагиваемых файлов.
